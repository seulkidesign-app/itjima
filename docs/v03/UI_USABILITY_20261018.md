# V03 조회 중심 UI 정리 · 2026-10-18

착수 조건: `v03.itjima.app` DNS 전파·Vercel Valid Configuration·검증된 HTTPS 200 확인 후 구현. 최종 주소는 [도메인 운영 기록](DOMAIN_OPERATION_20261018.md)을 따른다. V02 메인 전환 계획은 폐기했다.

## 변경 범위

- App 헤더에 작은 native details 계정 메뉴. 기존 이메일 로그인·가입·로그아웃·메시지·인증 구독과 정리 로직 유지. 48px 조작 영역, Escape 닫기/포커스 복귀, 포커스 이탈 닫기, 모바일 popover 최대 높이/스크롤 제공.
- 상세는 제목/메모/현재 상태 → 주요 일정 → 할 일 → 제작 조건 → 원본 가이드 → 협찬 정보/수정 진입 순. 기본 정보는 기존 ‘기본 정보 수정’ 버튼으로만 편집한다. 상태·일정 편집은 별도 ‘상태 수정’, ‘일정 수정’ 버튼으로 열고 취소하면 미저장 입력을 폐기한다.
- 저장 후 최신 조회 시 수정 폼은 닫힌다. RPC/버전·소유권·요청 UUID·receipt·실패 재시도 hook은 변경하지 않았다. 저장 중/충돌/결과 미확인 시 편집을 잠그며 중요한 안내와 같은 요청 재시도/최신 조회는 폼 밖 상단에 유지한다.
- ‘현재 운영 정보’를 ‘협찬 정보’로 변경하고 수동 출처 안내를 간소화. 최초 입력·원본은 계속 열람 가능하며 미입력/원문 미기재/불명확/사용자 제거 계약은 유지한다.
- V02 디자인 토큰·로고·폰트 계승 유지. V02 제품 코드·배포·데이터, migration, AI/OCR 변경 없음.

## 검증 구분

모바일 Chromium E2E는 가상 Supabase transport를 사용한다. 계정 메뉴 위치/Escape/320·390·430px 가로 넘침, 조회 섹션 우선순서, 상태·일정 명시적 열기와 취소를 신규 확인한다. 기존 기본 정보/상태/일정/날짜 제거의 충돌·동일 요청 재시도·중복 조작·로그아웃·늦은 응답 회귀는 새 수정 진입에 맞게 확인한다. 완료한 원격 SQL 계약 검증 및 migration은 재실행하지 않는다.

새 도메인의 실제 인증·협찬 조회·새로고침은 별도 합성 계정으로 실제 브라우저에서 검증하며 완료 후 계정과 데이터 잔여를 조회해 정리한다. iOS/Android 실기기 및 가입 이메일 redirect는 미검증 범위다. 배포는 현재 V03 브랜치 commit을 기존 itjima-v03-alpha Production에 반영하며 Source SHA를 최종 보고와 대조한다.

## 로컬 확인 결과

- 모바일 storage E2E 기존 56개 통과. 신규 usability 2개 통과: header 계정/Escape/모바일 폭, 조회 순서/수정·취소. 전체 실행에서 새 테스트의 팝오버를 닫지 않은 locator를 수정한 뒤 해당 2개를 재실행해 통과했다.
- 타입 검사·Vite production build 통과. git diff --check 통과. 관리자 비밀 값은 dist에서 검출되지 않았다.
- 원격 SQL/RLS 전체 검증과 기존 migration을 반복 실행하지 않았다. 실제 새 도메인에서 합성 계정 인증과 홈 협찬 조회 성공을 확인했다. 새 UI의 배포 후 브라우저 확인은 최종 보고로 구분한다.
