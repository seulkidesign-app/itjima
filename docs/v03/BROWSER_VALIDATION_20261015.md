# V03 실제 로컬 브라우저 검증 · 2026-10-15 (KST)

## SDK 검증과의 구분

[원격 SDK 검증](REMOTE_VALIDATION_20261015.md)은 Node에서 실제 SDK/앱 저장 함수를 호출한 검증이다. 이 문서는 그 커밋 `90416121`을 push한 후, 로컬 앱 `http://127.0.0.1:5183/`을 Codex 내장 브라우저에서 직접 조작한 별도 결과다. 브라우저 요청을 mock하거나 세션을 주입하지 않았다.

## 실제 브라우저 흐름과 결과

1. 관리자 API로 이번 검증에 한정한 임시 계정 1개를 만들었다. 식별 접두사는 `v03-qa-browser-`이며, 이메일 확인 완료된 합성 계정을 사용했다. 계정 주소·비밀번호·UUID는 기록하지 않는다.
2. 로그인 폼에서 이메일/비밀번호를 입력하고 실제 로그인 버튼을 눌렀다. `V03 계정 · 로그인됨`을 확인했다.
3. `브리프 가져오기` → `예시 넣기` → `원본 미리보기` → `Mock 결과 보기`를 진행했다. 원본 확인 단계와 mock 예시 안내를 확인했다.
4. 검토 전 `확인하고 저장`이 비활성임을 확인했다. 검증용 협찬 이름을 입력하고 가편/업로드 날짜의 연도를 명시했다. 9개 후보를 각각 확인했으며 불명확한 usage rights는 불명확 상태로 확인했다.
5. 9개 후보가 검토 완료된 후 저장 버튼이 활성화됐다. 버튼을 눌러 실제 원격 저장을 수행하고 `V03에 저장했어요.` 성공 표시 및 중복 제출 버튼 비활성화를 확인했다. 성공 UUID와 payload 내용은 로그로 출력하지 않았다.
6. 별도의 Management API 읽기 조회로 이 임시 계정의 committed import 1건, 협찬 1건, Task 5건, Review 9건을 확인했다. UI 성공 표시만으로 저장을 판정하지 않았다.
7. 브라우저 error 로그는 확인 시점에 0건이었다. 홈으로 복귀해 실제 로그아웃 버튼을 누르고 `V03 계정 · 로그인 필요` 상태를 확인했다.

## 자동화 중 관찰

내장 브라우저의 date input `fill`만으로는 표시값과 React 상태가 동기화되지 않아 후보 확인 버튼이 비활성인 상황이 있었다. 각 날짜를 다시 입력한 후 ArrowUp/ArrowDown과 Tab 키로 실제 변경 이벤트를 확정하자 검토를 완료할 수 있었다. 제품 코드는 수정하지 않았다. 일반 사용자 날짜 선택 UX 전체가 검증됐다는 의미는 아니다.

## 정리 및 제외 범위

- 임시 계정에 한정해 모든 V03 도메인 행과 import를 관계 순서대로 삭제하고 Auth 계정을 삭제했다. 해당 계정과 7개 테이블의 잔여 행이 모두 0건임을 확인했다. 이번 브라우저 검증에는 이미지 업로드를 사용하지 않았다.
- 브라우저 로그아웃 상태를 확인했고 화면 캡처는 검증 결과로만 확인했다. 계정·원문·payload·journal·스크린샷 파일은 Git에 넣지 않았다.
- Auth 이메일 발송·가입 확인·비밀번호 재설정, 브라우저에서의 실제 이미지 업로드 및 실패 복구는 이번 브라우저 검증 범위가 아니다. 이미지 저장·RLS·rollback·보상 삭제는 별도 원격 SDK 검증 결과를 참고한다.
- Migration은 재실행하지 않았다. V02/main, AI/OCR, 제품 코드를 변경하지 않았다.

## 수동 재현

새 검증 계정으로 V03 로그인 → 예시 브리프 → 원본 확인 → mock 결과 → 협찬 이름 및 연도 포함 날짜 입력 → 9개 후보 개별 확인 → 저장 성공·중복 제출 차단 확인 → DB 집계 확인 → 로그아웃·검증 데이터 정리 순서로 진행한다. 실제 사용자 계정과 실제 원문은 사용하지 않는다. 관리자 자격증명은 브라우저에 입력하지 않는다.
