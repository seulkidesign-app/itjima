# V03 · 약 2주 실제 협찬 검증

실제 Notion workflow를 최소 기준으로 진행 중인 여러 협찬을 관리한다. 시작 시 협찬 수, 상태, 가편/업로드일, 가이드 접근 방식과 불편을 기록한다. Notion과 원본은 비교·백업용으로 남겨 두며 과거 전체 이관을 강요하지 않는다.

## 핵심 질문

- 진행 중 협찬과 다음 할 일을 빠르게 찾는가?
- 가편·업로드 날짜와 상태를 혼동 없이 관리하는가?
- 원본 가이드 접근과 필수/금지 제작 조건 확인이 쉬워지는가?
- 같은 협찬을 여러 날 열어 수정할 이유가 있는가?
- 원문 미기재·불명확/판독 불가·수동 미입력·사용자 날짜 제거를 구분하는가?

성과와 광고 코드는 상세 기록 가능성을 확인하되 초기 홈 성공 지표로 삼지 않는다.

## 진행

1주차에는 텍스트/스크린샷 대조·실제 수동 등록·제작/가편 관리를 관찰한다. 샘플 체험은 원격 저장하지 않으며 실제 협찬 검증에 섞지 않는다. 중간에 누락·오해·입력 부담을 분류한다. 2주차에는 같은 협찬의 수정/컨펌/업로드와 재방문을 관찰한다. 모든 상태가 기간 내 발생한다고 가정하지 않고 실제 관찰과 fixture 검증을 구분한다.

다중 날짜, 연도 누락, 모순, 영상/자막 필수, 썸네일 금지, 플랫폼, 수정/컨펌, usage rights, 공개 유지 기간, 보류/복귀, 손상 이미지, 취소·중복·저장 실패를 포함한다.

외부 알림은 끈 상태다. 재방문하지 않은 이유를 필요 없음/열기 잊음/Notion이 편함/협찬 진행 없음/신뢰 문제로 구분한다. 재방문 부재만으로 제품 가치 부재를 확정하지 않는다. 알림 후속 검증은 별도 범위 결정 후 진행한다.

제품 이벤트에는 가명화 식별자·시간·진입 경로만 기록한다. 원문/이미지/광고 코드/성과 내용은 보내지 않는다. 페이지 조회만 아니라 같은 실제 협찬의 여러 날 수정과 관리 부담을 함께 본다.

잘못된 날짜·조건의 무확인 저장, 필수/금지 의미 반전, 데이터 유실·타 사용자 접근·V02 혼합은 blocker다. 명시된 판독 실패와 조용한 누락을 구분한다. 종료 시 실제 사례·미사용 이유·수정 부담·미검증 workflow·다음 최소 개선을 보고한다.

날짜를 제거하고 복원하는 실제 사용에서는 최초 날짜/원본과 같은 Task의 완료 여부가 보존되는지 관찰한다. 과거 null 날짜를 제거로 추정하지 않는다.
