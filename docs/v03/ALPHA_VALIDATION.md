# V03 · 모바일 실기기 및 2주 실사용 검증

제품 기준: `d837ea1f` / `codex/v03-influencer-mvp` (2026-10-16 정리). 이 문서는 기존 검증 결과와 앞으로 작성할 체크리스트·기록 양식을 구분한다. 이번 문서 정리에서 제품 테스트·원격 검증·migration을 재실행하지 않았다.

## 현재 사용할 수 있는 범위

- 실제 계정 로그인, 본인 협찬 홈·상세 조회, 새로고침 후 재조회.
- 빈 입력에서 실제 수동 등록: 협찬 이름(필수), 플랫폼·메모·가편 전달일·업로드 예정일(선택), 자유 할 일·제작 조건 추가/수정/삭제, 원본 텍스트·이미지 대조, 요약·명시적 확인 후 저장. manual 출처와 최초 입력 snapshot을 보존한다.
- 저장 후 이름·메모와 명시한 콘텐츠의 플랫폼 수정/취소, 상태 7종 변경·건너뛰기·복귀, 기존 할 일 완료/되돌리기, 가편·업로드 일정 수정·명시적 제거·복원.
- 기존 협찬에 후속 가이드 텍스트·이미지 추가: 원본 미리보기·명시적 확인, 최초/후속 구분, 등록 순서·등록 일시, private 이미지 재열람. 등록 일시는 브랜드 컨택 일자가 아니다.
- 홈의 진행 중/완료/보류 구분, 다음 미완료 할 일, 기한 지남·기한 없음 표시. 협찬 상태와 할 일 완료는 서로 자동 변경하지 않는다. 후속 가이드도 일정·할 일·조건·상태를 자동 변경하지 않는다.

샘플 체험은 로컬 mock이며 실제 추출 결과가 아니고 원격 저장하지 않는다. 실제 등록에는 mock 값 자동 채움이나 AI/OCR이 없다. 입력하지 않은 항목을 원문 미기재로 판단하지 않는다.

저장 후 자유 할 일·조건의 내용 편집/추가/삭제, 원본 가이드 편집/삭제, 전체 변경 이력 UI는 현재 제공 범위가 아니다. 성과·광고 코드·콘텐츠 링크·컨택 일자의 입력/편집을 검증 완료 기능으로 간주하지 않는다. 해당 항목이 필요하면 기존 Notion에 보관하고 별도 요구로 기록한다. 알림·자동 추출·자동 상태 전이는 사용하지 않는다.

## 모바일 실기기 체크리스트 — 아직 전 항목 미검증

iOS Safari와 Android Chrome에서 각각 별도 사본을 작성한다. 처음에는 합성 데이터로 진행하고, 안전한 기본 흐름을 확인한 뒤 실제 협찬을 사용한다. 기존 기능 검증 스크립트나 migration의 재실행을 요구하는 목록이 아니다.

기기 기록: 점검일 `____` / 기기 모델 `____` / OS `____` / 브라우저·버전 `____` / 앱 commit `____` / 언어·시간대 `____` / 화면 방향·크기 `____` / Wi-Fi·모바일망 `____`.

## 2주 운영 방법

시작 전 Notion·원본을 비교/백업용으로 유지한다. 전체 과거 이관을 요구하지 않고 실제로 진행 중인 일부 협찬부터 선택한다. 기한 판단은 초기에는 원본/Notion과 대조한다. 알림은 제공하지 않으며 켜져 있다고 가정하지 않는다.

기간은 시작일부터 14일이다. 1주차에는 수동 입력·원본 대조·다음 할 일 확인 부담, 2주차에는 같은 협찬 재방문·수정/컨펌·업로드 관리와 후속 가이드 접근을 관찰한다. 모든 상태나 문제가 기간 내 발생한다고 가정하지 않는다. 발생하지 않은 흐름을 만들기 위해 실제 데이터를 변경하지 말고 ‘기회 없음’으로 남긴다. 합성 점검과 실제 사용 기록은 구분한다.

핵심 질문은 다음과 같다.

- 진행 중 협찬과 다음 할 일을 찾는 시간이 줄었는가?
- 가편/업로드 날짜·상태·완료를 혼동하지 않았는가?
- 원본 가이드·제작 조건을 필요할 때 찾았는가?
- 같은 실제 협찬을 여러 날 다시 열거나 수정할 이유가 있었는가?
- Notion 이중 입력·확인 부담, 입력 손실, 저장 신뢰 문제는 어느 정도였는가?

현재 자동 analytics 수집이 구현됐다고 전제하지 않는다. 아래 값은 참여자가 직접 기록하는 관찰값이며, 못 잰 값은 공란 대신 ‘미측정’으로 쓴다. 페이지 조회 수나 재방문 부재만으로 가치 유무를 확정하지 않는다.

미사용 이유는 `관리할 진행 없음 / 열기 잊음 / Notion이 편함 / 입력 부담 / 신뢰 문제 / 기기·연결 문제 / 기타`로 구분한다. 알림 부재에 따른 미사용은 별도 관찰이며 알림 구현 요청으로 자동 전환하지 않는다.

## 문제 심각도와 알파 중단 기준

| 심각도 | 예시 | 조치 |
| --- | --- | --- |
| P0 · 실사용 차단 | 타인 협찬/이미지 노출, V02 데이터 혼합, 저장된 데이터·최초 원본/snapshot/Review 유실·덮어쓰기, 사용자 확인 없는 저장/조용한 잘못된 일정·조건 또는 의도하지 않은 자동 변경 | 의심만으로 해당 실사용 쓰기를 즉시 멈추고 확인. 노출 범위·데이터 무결성이 불명확하면 알파 전체 중단 |
| P1 · 주요 흐름 실패 | 등록/수정/원본 열람 불가, 반복 저장 오류·결과 불명확, 날짜 의미 혼동으로 잘못된 행동 위험. 아직 노출·유실이 확인되지는 않음 | 해당 흐름 중지, Notion/원본으로 관리. 안전한 우회가 없거나 반복되어 핵심 관리가 불가능하면 알파 중단 |
| P2 · 사용성 개선 | 우회 가능한 배치/문구·터치 불편, 긴 메모 가독성, 추가 확인 동작 부담 | 이슈 기록 후 제한적으로 계속 사용, 빈도·시간 비용으로 우선순위 판단 |

기능 미지원·해당 기간 기회 없음·명시된 저장 전 입력 소실은 사실대로 별도 기록한다. 다만 실제 기한 관리나 안전한 사용을 막으면 영향에 따라 P1/P0로 올린다. ‘아직 원인 모름’을 낮은 심각도로 취급하지 않는다.

저장 결과가 불명확하면 같은 요청 재시도/재조회로 현재 DB 상태를 확인한다. 새 요청을 연속 생성하거나 저장된 이미지를 임의 삭제하지 않는다. 새로고침/이탈/로그아웃은 이미 시작된 서버 transaction의 rollback을 보장하지 않고, 메모리 입력·요청 UUID는 사라질 수 있다. 복구가 불명확하면 사용을 멈추고 담당자 확인을 기다린다.

재개 조건: 영향 범위·데이터 상태 확인, 필요한 복구와 수정, 관련 흐름의 합성 데이터 검증 및 사용자 확인. 실기기 결함이면 해당 기기에서도 확인한다. 재개를 위해 기존 migration이나 완료된 검증 전체를 일괄 재실행하지 않는다.

## 기록 보관 원칙

이 파일에는 빈 양식과 가명·집계·비식별 관찰 결과만 둔다. 비밀 키·토큰·계정/세션·DB/Storage 경로·실제 협찬 원문·이미지·브랜드명·메모·정확한 계약 일정·광고 코드·성과·실제 링크는 넣지 않는다. 민감 자료가 필요한 진단은 Git 밖의 접근이 제한된 보관 경로에서 별도로 취급한다. 문서/이슈의 화면 증거는 합성 데이터로 재현하거나 내용을 제거한 뒤 검토한다.
