# 협찬 상세 조회 P0 · 2026-10-15 (KST)

## 구현

- 저장 완료 후 `#/collaborations/<UUID>`로 이동한다. 저장 전 입력의 메모리/이미지 URL은 정리한다.
- 상세 URL에서 UUID를 읽고 현재 V03 사용자 소유 조건과 기존 RLS를 적용해 Supabase 관계 조회를 수행한다. 새로고침·직접 URL 진입 모두 다시 조회한다. 브라우저에 협찬 원문 캐시를 저장하지 않는다.
- 브랜드/캠페인 이름과 저장된 상태, Task 기반 가편/업로드 날짜, 콘텐츠별 할 일, 제작 제약조건, 원본 텍스트와 private 이미지를 표시한다. 원본 가이드 바로가기 버튼은 상세 라우트를 바꾸지 않고 해당 구역으로 이동·포커스한다.
- Review의 `not_mentioned`는 원문에 미기재, `uncertain`은 불명확/판독 불가로 구분한다. 정보가 없는 상황을 미기재로 임의 확정하지 않는다. mock 출처도 표시한다.
- 비공개 원본 이미지는 명시적 버튼 후 인증된 Storage download로 가져온다. 공개 URL을 만들지 않으며 blob URL은 화면 이탈 시 해제한다. 이미지 접근 오류와 재시도도 제공한다.
- 로그인 필요, 로딩, 잘못된 주소, 협찬 없음/접근 불가, 연결 오류와 재시도 상태를 구현했다. 15초 조회 제한 및 늦은 응답/이전 라우트 응답 무시를 적용했다. 로그아웃 시 상세·원본을 숨긴다.

## 자동화 · 실제 DB에 접근하지 않는 테스트

- `npm test`: 6개 파일, 53개 단위/SQL·RLS 테스트 통과. 상세 조회 소유자·ID 필터, 취소 signal, 잘못된 UUID의 요청 차단, 오류 분류 및 날짜 정보 상태 구분을 포함한다.
- `npm run test:e2e`: 기존 모바일 브리프 E2E 8개 통과.
- `npm run test:e2e:storage`: 상세·저장 Supabase 응답 mock E2E 10개 통과. 직접 링크에서 로그인, 320px 레이아웃, 일정/조건 표시, private 이미지 실패·재시도, 미기재/불명확, RLS-hidden/없는 협찬, 네트워크 재시도, 로그아웃 비공개 전환, 잘못된 URL, 로딩, 15초 제한, 저장 후 이동·새로고침과 V02 세션 보존을 포함한다.
- 타입 검사·프로덕션 빌드 통과. 추가 의존성은 없다.
- 초기 503 오류 E2E에서 SDK 내부 재시도로 오류 표시가 지연되는 문제가 확인돼 상세 쿼리의 자동 재시도를 끄고 명시적 재시도 버튼/제한 시간을 제공했다. 수정 후 관련 테스트가 통과했다.

## 실제 브라우저 + 실제 원격 Supabase

로컬 개발 앱 `http://127.0.0.1:5183/`에서 별도 식별 가능한 임시 계정 1개와 합성 예시 브리프를 사용했다. 로그인·저장·상세 조회 요청을 mock하지 않았다. 계정 식별자·비밀번호·토큰·원문·실제 협찬 UUID는 이 문서와 로그에서 제외했다.

1. 실제 V03 로그인 → 예시 브리프 → 원본 미리보기 → mock 후보 9개 명시적 확인 → 실제 저장.
2. 상세 URL 이동과 실제 관계 조회 성공. 협찬 이름·일정·할 일·원본 구역 표시 확인.
3. 같은 상세 URL에서 새로고침 후 동일 협찬과 날짜·불명확 조건 재조회 성공.
4. 원본 가이드 바로가기의 포커스 이동 및 상세 URL 유지 확인. 가로 넘침 없음, 확인 시점 브라우저 error 로그 0건.
5. 별도 원격 읽기 집계로 임시 계정의 committed import 1개, 협찬 1개, Task 5개, Review 9개 확인.
6. 같은 상세 URL에서 로그아웃하면 이름과 원본이 사라지고 로그인 안내로 전환됨을 확인. 이후 홈으로 복귀했다.
7. 임시 계정과 모든 검증용 V03 행을 삭제했다. Auth 계정 및 7개 테이블 잔여 0건 재확인.

## 범위·한계

- 이번 실제 브라우저 검증은 텍스트 원본을 사용했다. 상세 화면의 이미지 보기·실패/재시도는 mock E2E로 검증했다. 실제 private Storage 권한과 이미지 bytes 저장/보상 삭제는 별도의 [원격 SDK 검증](REMOTE_VALIDATION_20261015.md) 기록이며 이번 브라우저 검증과 혼동하지 않는다.
- 모바일 자동화의 date fill만으로 React 상태가 갱신되지 않아 실제 키보드 변경 이벤트로 확정했다. 해당 자동화 환경의 관찰 사항이며 제품 날짜 입력 코드는 변경하지 않았다.
- 실제 타인 소유 협찬의 접근 거부는 기존 원격 RLS 검증과 이번 RLS-hidden mock 테스트로 확인한다. 이번 실제 브라우저에서 두 번째 사용자 검증은 반복하지 않았다.
- 편집·홈 목록·빠른 입력·AI/OCR·알림은 이번 범위가 아니다. V02/main과 기존 migration은 변경하지 않았고 migration도 재실행하지 않았다.
