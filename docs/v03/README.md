# V03 · 인플루언서 브랜드 협찬 관리

이 디렉터리가 새 V03의 기준이다. 과거 roadmap의 일정 UX, AI trust 및 resurfacing 계획은 새 V03 범위가 아니다. V02 포트폴리오 앱은 그대로 보존한다.

## 실제 workflow가 최소 기준

현재 Notion에서 실제 여러 협찬을 관리하는 필드: 브랜드/캠페인, 상태, 컨택 일자, 가편 전달일, 업로드 예정일, 업로드 플랫폼, 가이드, 콘텐츠 링크, 광고 코드, 성과, 메모.

상태는 `제안/협의 → 제작 중 → 가편 전달 → 컨펌 중 → 업로드 예정 → 완료`이며 별도 `보류`가 있다. 사용자가 상태를 선택하며 역방향·단계 건너뛰기를 허용한다. 날짜 도래, AI 추출, 작업 완료로 상태를 자동 전이하지 않는다.

## 핵심 가치와 UX

**원본 브리프 → 일정 + 해야 할 일 + 제작 제약조건 → 검토/수정 → 확인 → payload → 저장**

가편과 업로드 날짜, 영상·자막 필수, 금지 썸네일 요소, 공개 유지 기간, 업로드 플랫폼, 수정/컨펌 절차, usage rights를 함께 관리한다. 사용자가 원문과 비교하여 확인하기 전에는 최종 Collaboration/Task/Constraint를 생성하지 않는다. 여러 날짜의 연도·시각·의미를 임의 확정하지 않는다.

사용자 UI의 단위는 협찬 한 건이다. Collaboration / Content / Task / Source / Constraint / Review / Import는 내부 구조이며 별도의 복잡한 프로젝트 관리 화면을 요구하지 않는다. 기본 콘텐츠는 한 개로 시작한다.

홈의 우선순위는 진행 중 협찬, 다음 할 일, 가편 전달일, 업로드일, 진행 상태, 가이드 접근이다. 성과·광고 코드·콘텐츠 링크·메모는 모델과 상세에 포함하되 성과 대시보드를 초기 홈 중심에 두지 않는다.

## 구현 순서 및 분리

독립 기반 이후 `브리프 가져오기 → 협찬 상세 → 홈 → 빠른 입력` 순서다. 텍스트와 스크린샷을 지원하고 링크는 참조로만 보관한다.

- `apps/v03/`는 별도 package/lockfile/실행/빌드/환경 설정을 사용한다.
- V03은 별도 Supabase 프로젝트·인증 세션·Storage·저장 경로를 사용한다. V02 fallback 및 기존 데이터 이관은 없다.
- V02 root 코드, migrations, 알림/push, 재발견, 자연어 일정 자동 저장을 가져오지 않는다.
- V02 기준점: main 및 archive/v02-portfolio-20261010의 `b47bb09a00abd86d3d6e08ec17c2ec65be0e5389`. 실제 운영 배포/복원 상태는 별도 확인 대상이다.
- AI/OCR은 아직 연결하지 않는다. mock은 예시이며 원본에서 추출한 사실이라고 표시하지 않는다.
- 초기 약 2주 실제 협찬 검증은 알림 없이 진행한다.

재발견, 범용 캘린더, 자동 소셜 게시, 자동 성과 분석, 청구·정산·CRM·협상·팀 관리는 초기 범위에서 제외한다.
