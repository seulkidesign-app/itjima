# Itjima V0.2 Interaction Architecture

## Why this exists

V0.1 validated that people liked capturing schedules and tasks in natural language, but beta feedback showed two recurring problems:

1. AI interpretation was not always trustworthy.
2. After capture, users could not always tell what was saved or what action would happen next.

V0.2 therefore reduces interaction rules before adding features.

## Product principle

> 그냥 남기면, 잊지마가 먼저 정리한다. 결과는 사용자가 확인하고, 필요한 순간 다시 만난다.

The user should not have to learn Itjima's internal state model.

## Portfolio AS-IS → TO-BE

### AS-IS · V0.1

빠르게 남길 수 있었지만, AI가 해석한 결과와 이후 행동을 사용자가 다시 정리해야 했습니다.

### TO-BE · V0.2

AI가 먼저 정리하고 결과를 확인시킨 뒤, 각 상태에서 필요한 행동만 보여줍니다.

빠르게 남기고, 필요한 순간 다시 만난다는 핵심 경험은 유지합니다.

## Interaction rules

1. **One target = one action.** A tap area must never trigger a different action depending on hidden state.
2. **Visible action names describe the result.** Prefer `완료`, `수정`, `시간 정하기` over metaphorical labels for core actions.
3. **Gestures are shortcuts, never the only path.** Swipe can remain for speed, but the same action must be visible.
4. **AI structures first; the user reviews.** Do not silently save an AI interpretation that has not been shown to the user.
5. **State changes show a result.** After save, edit, completion, or reminder changes, show what changed.
6. **Internal states stay internal.** `date = null` may exist in data, but users should not need to understand a special `날짜 없음` workflow.
7. **Completion is contextual.** Schedule/task-like items can be completed; memories do not receive a global `완료` action.
8. **One primary action per decision surface.** Secondary actions must not compete with the main next step.

## State × action matrix

| State | User sees | Primary action | Secondary action | Must not happen |
| --- | --- | --- | --- | --- |
| Captured, AI interpreted | Parsed title + date/time/type | Confirm/save | Adjust interpretation | Silent save without showing result |
| Captured, ambiguous time | Parsed result + explicit ambiguity | Choose the missing time/date | Keep for later | Re-enter the whole sentence |
| Scheduled item | Time + title + reminder state | Complete when applicable | Edit / reminder | Tapping unrelated areas opens time setup |
| No-time actionable item | Content without system jargon | Set time when needed | Complete when applicable | Force delete + re-entry to schedule it |
| Memory / archive item | Content + resurfacing context | Open / revisit | Move or edit if needed | Show `완료` by default |
| Completed schedule/task | Completed state | — | Reopen/edit if supported | Hidden state change with no feedback |

## V0.2 scope

### P0 · QA before re-test

- Prevent unintended transition from schedule add into reminder/time setup.
- Fix/retest natural-language time parsing regressions such as `3시 반`.
- Prevent duplicate schedule creation.
- Remove overlapping card touch targets, including iPad behavior.

### P1 · Core UX

- Make AI interpretation a clear review step: **AI first → result shown → confirm/adjust**.
- Make schedule-card actions explicit and independent.
- Let no-time items continue to a useful next action without deletion or re-entry.
- Show save/update outcome clearly.

### P2 · Product philosophy, light touch

- Keep re-discovery visible as the home for memories and no-time records.
- Do not redesign the entire archive before the V0.2 usability re-test.

## Re-test questions

1. Can a first-time user explain what each visible schedule-card action will do?
2. Can a user move a no-time record forward without deleting and retyping it?
3. Can users distinguish AI interpretation from the final saved result?
4. Do users still perceive natural-language capture as fast?
5. Do any taps lead to a different action than the user expected?
