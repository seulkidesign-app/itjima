# V0.3 · AI Trust Floor

## Goal

Raise the minimum trust level required for real-use testing without turning V03 into a broad AI feature project.

## Product contract

1. Clear → interpret correctly.
2. Ambiguous → ask or preserve the original input.
3. Invalid / unsupported → never silently save a different schedule.
4. A schedule is not automatically a reminder; notification intent must be explicit.
5. The model never writes a schedule directly. Model-normalized text must pass the deterministic safety gate again.

## Implemented

### Deterministic trust floor

- Korean contextual clocks: `저녁 7시`, `밤 10시`, `새벽 2시`
- Korean word-form clocks: `오후 세시`, `저녁 일곱 시`
- Compound relative offsets: `한 시간 반 뒤`, `2시간 30분 후`
- Invalid date/time guard: `2월 30일`, `25시`, `75분`, invalid 24h clocks
- Broad dayparts such as `아침`, `점심`, `저녁`, `퇴근 후` are context, not exact clocks
- Midnight/date-boundary expressions fail closed instead of guessing
- Unknown date shorthand cannot silently fall through to today's clock time

### Safe model fallback

- Conservative `schedule` normalization mode on the existing model endpoint
- Capture uses the model only when local date language cannot be resolved safely
- Structured model result: `normalized | ambiguous | unsupported | not_schedule`
- Model cannot invent date, time, AM/PM, recurrence or reminder facts
- Bare 1–12 hour expressions are not semantically guessed
- Model output is re-validated by the local trust gate before commit
- API failure or rejected output keeps the raw inbox item unchanged
- Model calls remain environment-gated

### Dogfood QA fixes

- `내일 아침 챙겨먹기` must not become an invented 09:00 schedule
- `내일 오후 3시 치과` must not ask `몇 시로 기억할까요?` again
- Ambiguity UI preserves the user's original sentence instead of hiding the entered time
- Exact schedule input defaults to reminder OFF
- Reminder is created only from explicit language such as `30분 전에 알려줘`
- Home auto-scroll / turn ordering was fixed separately on `main` so dogfooding is not blocked

## Still open

- Decide safe UX for expressions like `내일 모레 청소하기` instead of silently choosing one date
- Dogfood the Preview with more real Korean inputs and add failures as regression cases
- Enable the model flag only when an API-backed Preview test is intentionally run
- Do not merge V03 until Preview QA is complete

## Out of scope

- Multi-event creation
- Recurrence
- Location/weather context
- Automatic rediscovery
- Large LLM evaluation infrastructure
- Archive IA redesign

## Exit rule

V03 can move toward merge only when release tests and Preview are green and the remaining high-severity dogfood failures are understood. New feature ideas stay in backlog.
